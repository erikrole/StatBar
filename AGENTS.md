# Monitor agent notes

Public app name: **Monitor** (formerly StatBar). Follow [the shared family design language](docs/brand/FAMILY.md). Keep `StatBar` technical identifiers, storage, updater routing and package filenames stable; use Monitor in user-facing copy.

Follow `../AGENTS.md`. Native macOS menu-bar app, xcodegen project (`project.yml`), Swift 6 language mode, deployment target macOS 27 (all projects target macOS 27; use current APIs: Observation `@Observable`, Swift concurrency).

- Concurrency: `StatMonitor`, the popover UI and the app delegate are `@MainActor`. Sampling is one `Task.sleep` loop (`StatMonitor.startSampling`) with a one-second tolerance while the popover is closed and a quarter-second tolerance while it is open. Reachability is a single `NWPathMonitor` cancelled on pause; screen sleep/wake are async sequences. Pause cancels sampling/reachability, invalidates detail results and cooperatively cancels detail work. Retain the one in-flight detail slot until the OS read returns; never start extra workers after a timeout. Fan/network detail reads stay independent of this slot. Wake resets counter/process baselines. The menu bar uses a fixed-width status item and applies a new title or image only when `MenuBarPresentation` changes. The app is an AppKit `@main` delegate; do not add a SwiftUI `App` scene.
- Network: route changes clear old identity/rates and refresh details immediately. Unknown VPN state must not produce disconnect events. Disconnects and unavailable counters advance history with zero samples.
- After editing `project.yml` or adding Swift files, run `xcodegen generate`. `./scripts/check-macos.sh test` runs Debug tests; `release-test` runs the full optimized suite; `benchmark` runs only optimized reader benchmarks. Release test modes use `ENABLE_TESTABILITY=YES`; distribution archives do not. Raw logs and result bundles belong under ignored `build/`, never in commits.
- Local launch: `./script/build_and_run.sh --verify` (also the Codex Run action). Set `STATBAR_CONFIGURATION=Release` for optimized local runs. These local builds are unsigned; publishing uses the separate release workflow. Run launch/restart checks after tests finish: the script's process replacement also stops a running StatBar test host.
- Color: preserve the metric palette: CPU/cores/downloads blue, GPU purple, disks teal, uploads orange, healthy memory/battery/network green. Keep warning and critical colors distinct; compact-layout work must retain these colors.
- `python3 scripts/measure-idle.py <app-executable>` measures a temporary copy without stopping the user's running app or persisting notification preferences. Compare Release builds on the same Mac under comparable workloads; live-reader benchmarks do not establish battery impact or long-term stability.
- UI: keep the 360 × 600-point overview compact. CPU/GPU share a row; technical details use native disclosures. Persist disclosure and process-sort preferences with `@AppStorage`, since the hosting controller is destroyed when the popover closes. The fixed footer contains Activity Monitor and a settings menu. Keep histories on Canvas and never retain a hidden hosting controller.
- Launch: normal copies elect the oldest process by launch date, then PID, and asynchronously allow an older updater host five seconds to exit. Never block the main thread or defer to a younger copy. Initialize Login Items only after winning. `--report`, `--snapshot` and `--measure-idle` skip the election, Login Items setup and update checks, and suppress notifications through process-local defaults. Headless reports/snapshots use prohibited activation policy and are excluded from normal elections. The idle profiler also gives its temporary app a unique bundle identity.
- Releases: `scripts/release-macos.sh` defaults to `--stage`: signed local ZIP, checksum and provenance, without submitting the app to Apple. Explicit `--notarize` uploads the app, requires an existing notarization profile/key, checks Apple's Accepted result, staples and verifies Gatekeeper after fresh extraction. Both modes require committed, clean source and an empty output directory, and build a `git archive` snapshot. Obtain authorization for the Apple upload separately from local preparation. Neither mode publishes a GitHub release. Current 1.0 acceptance state is in `docs/1.0-readiness.md`.

AppUpdater integration: `AppUpdate.swift` owns the pinned package instance. Keep automatic checks Release-only and exclude tests/CLI helpers. Permit updater termination only after `isAwaitingRelaunch`, then retain host save/busy/restore guards. Never add a forced-exit fallback for these guards.
